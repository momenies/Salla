# 🛒 منقذ السلات

**تطبيق سلة يستعيد المبيعات الضائعة عبر تذكير واتساب تلقائي**

٧ من كل ١٠ عملاء يتركون سلاتهم دون شراء. هذا التطبيق يذكّرهم — تلقائياً، وبصوت متجرك.

</div>

---

## ما الذي يفعله؟

| القدرة | الشرح |
|---|---|
| **تذكير السلات المتروكة** | يستقبل حدث السلة من سلة، ينتظر المهلة التي تحدّدها، ثم يرسل رسالة واتساب برابط السلة نفسها |
| **متابعة رحلة الطلب** | شكر عند الطلب، تحديث عند الشحن، طلب تقييم بعد التسليم، تأكيد الدفع عند الاستلام |
| **لوحة مؤشرات حقيقية** | الإيراد المستعاد بالريال، نسبة الاستعادة، منحنى سبعة أيام، سجلّ كل رسالة وسبب فشلها |
| **قناتان للإرسال** | Meta الرسمية (للإنتاج)، أو ربط بالباركود (للتجربة السريعة) |
| **قواعد تحمي سمعتك** | ساعات هدوء، سقف يومي، إلغاء تلقائي لأي تذكير إذا أكمل العميل طلبه |
| **الفواتير والعملاء** | ميزات إضافية تُباع كـ Add-ons عبر اشتراكات سلة |

## التشغيل محلياً

```bash
cd template
npm install
cp .env.example .env      # ثم املأ مفاتيح سلة
npm run dev               # http://localhost:8082
```

بلا مفاتيح سلة سيعمل التطبيق ويعرض **صفحة إعداد** تشرح ما ينقص بالضبط — لن ينهار ولن يرميك في رسالة غامضة.

**الحد الأدنى للتشغيل:**

```env
SALLA_OAUTH_CLIENT_ID=...
SALLA_OAUTH_CLIENT_SECRET=...
SALLA_OAUTH_CLIENT_REDIRECT_URI=http://localhost:8082/oauth/callback
SALLA_WEBHOOK_SECRET=...
SESSION_SECRET=<node -e "console.log(require('crypto').randomBytes(32).toString('hex'))">
DATABASE_STORAGE=database.sqlite
CRON_SECRET=<أي نص عشوائي طويل>
```

## الاختبارات

```bash
npm test        # ٧٦ اختباراً: وحدة + تكامل صفحات + عزل المتاجر
npm run lint    # فحص بناء الملفات وتحميل الوحدات
```

اختبارات `test/pages.test.js` تُرندر كل صفحة ببيانات حقيقية، و`test/isolation.test.js` تمنع عودة تسرّب البيانات بين المتاجر.

│   ├── automation.js      محرّك السيناريوهات والجدولة وعامل الطابور
│   ├── messaging.js       اختيار القناة، ساعات الهدوء، السقف اليومي

├── Actions/               ملفات أحداث سلة (اصطلاح سلة الرسمي)

## النشر على Google Cloud Run

```bash
gcloud run deploy cart-rescuer \
  --source template \
  --region me-central1 \
  --allow-unauthenticated \
  --set-env-vars NODE_ENV=production,TRUST_PROXY=1,DISABLE_INTERNAL_TICKER=1 \
  --set-secrets SESSION_SECRET=session-secret:latest,SALLA_OAUTH_CLIENT_SECRET=salla-secret:latest
```

بعد النشر:

1. **حدّث Callback URL** في بوابة الشركاء إلى `https://<رابطك>/oauth/callback`
2. **وجّه الويبهوك** إلى `https://<رابطك>/webhook`
3. **اضبط المجدول** — Cloud Scheduler كل ٥ دقائق على:
   `https://<رابطك>/internal/cron/<CRON_SECRET>`
4. **استبدل SQLite** بـ Postgres أو MySQL عبر `DATABASE_URL` — ملف SQLite داخل الحاوية يضيع مع كل نشر.

> **مهم:** لا يقلع التطبيق في الإنتاج بلا `SESSION_SECRET` و`SALLA_WEBHOOK_SECRET`. هذا مقصود: العمل بلا سرّ جلسات يعني إمكان تزوير جلسة أي تاجر، وبلا سرّ ويبهوك يستطيع أي أحد إرسال أحداث مزيّفة.

## إضافة ميزة مدفوعة جديدة

عدّل `config/features.js` فقط:

```js
{
  key: "my_feature",
  name: "اسم الميزة",
  description: "ماذا تفعل للتاجر",
  icon: "zap",
  free: false,
  routes: ["/my-feature"],
  price: "٢٩ ر.س / شهرياً",
  addonMatch: ["my_feature", "اسم الإضافة في سلة"],
}
```

صفحة الباقات والقائمة الجانبية وحارس الصلاحيات يلتقطونها تلقائياً. أنشئ Add-on بنفس الاسم في بوابة الشركاء، وإن لم يتعرّف التطبيق على الإضافة فلن يفتح شيئاً — وستجد نص الحدث الخام في صفحة الباقات لتضبط `addonMatch`.

## نقاط تشغيلية

| المسار | الغرض |
|---|---|
| `GET /healthz` | فحص صحة شامل (قاعدة البيانات، الذاكرة، مدة التشغيل) |
| `GET /readyz` | فحص جاهزية لموازن الأحمال |
| `POST /webhook` | استقبال أحداث سلة |
| `ALL /internal/cron/:secret` | دورة المجدول (تقبل السرّ أيضاً في ترويسة `x-cron-secret`) |

## الأمان

- توكن مستقل لكل متجر، مع تجديد تلقائي قبل الانتهاء
- تحقّق ويبهوك بالتوقيع (HMAC-SHA256) أو التوكن، بمقارنة ثابتة الزمن
- حماية CSRF على كل نموذج، وحدّ للطلبات على المسارات الحسّاسة
- سياسة محتوى صارمة (CSP) مع nonce لكل طلب
- إخفاء تلقائي للتوكنات في السجل
- تهريب كامل للمخرجات في القوالب
